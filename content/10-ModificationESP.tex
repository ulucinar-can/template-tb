\chapter{Modification apportée au programme de l'ESP32}

\section{Introduction}
Ce chapitre traite des modifications et améliorations apportées à l'interface web. La correction d'un chargement infini et l'ajout de la mesure du courant ont été implémentés.

\section{Analyse de l'espace mémoire}
Le compilateur de l'environnement Arduino permet d'évaluer l'espace mémoire occupé au sein de l'ESP32. L'issue de la compilation fournit les informations suivantes concernant l'allocation mémoire :

\begin{quote}
  Le croquis utilise 979768 octets (74\,\%) de l'espace de stockage de programmes. Le maximum est de 1310720 octets.

  Les variables globales utilisent 45324 octets (13\,\%) de mémoire dynamique, ce qui laisse 282356 octets pour les variables locales. Le maximum est de 327680 octets.
\end{quote}

En ce qui concerne la taille des fichiers sources, le code propre à l'ESP32 représente 9,9~ko, tandis que celui définissant l'interface web occupe 10,6~ko.

La majorité de la mémoire est occupée principalement par les bibliothèques liées au Wi-Fi et au serveur web. Il a tout de même été possible de réaliser les modifications apportées à l'ESP32.

\section{Modifications et corrections sur la page web et la communication}
La page web actuelle permettait, depuis le travail de bachelor précédent, d'afficher des tracés de la position. Cependant, des problèmes de connexion à l'interface web subsistaient.

Une volonté d'afficher le courant a été exprimée, ce qui a dès lors été implémenté.

\subsection{Correction du chargement infini}
Lors de la connexion à l'interface utilisateur, il arrivait que celle-ci présente un chargement infini.

À la suite de recherches, la raison a été trouvée dans les fonctions de réponse du serveur, à savoir \texttt{server.send()}. La réponse renvoyait initialement le code 250. En se basant sur les références de statut recommandées pour le protocole HTTP \cite{HTTPStatut}, ce code ne constitue pas un standard employé pour indiquer le succès d'une requête. La page web ne sait donc pas comment interpréter cette valeur, et il arrive qu'elle l'accepte ou non selon les cas. Dès lors, ce code a été remplacé par une valeur mieux connue des serveurs web, à savoir 200, qui indique un simple \texttt{OK}.

\subsection{Ajout de la mesure du courant}
À la demande de Monsieur Girardin, la mesure de courant a été ajoutée sur l'interface web.

Pour commencer, il a fallu modifier la fonction \texttt{SendFloatAsText} afin qu'elle puisse accepter 8 valeurs. Il a d'abord été nécessaire de modifier la taille du buffer de transmission \texttt{TX\_BUF\_LEN} en la faisant passer de 64 à 128. Quatre nouvelles variables ont également été ajoutées aux paramètres de la fonction \texttt{SendFloatAsText}. Les modifications donnent dès lors :

\begin{minted}{c}
#define TX_BUF_LEN 128
...
void SendFloatAsText(float f0, float f1, float f2, float f3, float f4, float f5, float f6, float f7)
{
    char str[TX_BUF_LEN];
    int i = 0, j = 0;

    str[i++] = '\x02'; // start bit

    i += ftoa(f0, &str[i], 3); str[i++] = ',';
    i += ftoa(f1, &str[i], 3); str[i++] = ',';
    i += ftoa(f2, &str[i], 3); str[i++] = ',';
    i += ftoa(f3, &str[i], 3); str[i++] = ',';
    i += ftoa(f4, &str[i], 3); str[i++] = ',';
    i += ftoa(f5, &str[i], 3); str[i++] = ',';
    i += ftoa(f6, &str[i], 3); str[i++] = ',';
    i += ftoa(f7, &str[i], 3);

    str[i++] = '\x03'; // stop bit

    for (j = 0; j < i && j < TX_BUF_LEN; j++) {
        txBuffer[j] = (uint8_t)str[j];
    }
    txLength = i;
    txIndex = 0;

    SCI_enableInterrupt(SCIA_BASE, SCI_INT_TXFF);
}
\end{minted}

Le code du côté de l'ESP32 doit également être modifié afin qu'il puisse accepter davantage de valeurs.

Tout d'abord, il faut augmenter la taille du buffer dédié à la communication UART. Ceci se réalise en faisant passer la constante \texttt{UART\_BUFFER} de 64 à 128.

Ensuite, lorsque la trame est entièrement reçue, il faut porter à 8 la valeur maximale de la boucle \texttt{while(...)} gérant la conversion des données.

Pour terminer, il faut que l'interface web puisse retrouver les valeurs de courant. De nouvelles balises XML ont dès lors été créées afin d'indiquer à l'interface web les valeurs de courant. Celles-ci sont déclarées sous la forme \texttt{<curIndX>}, où X représente un numéro allant de 1 à 4 selon l'inducteur.

Ceci donne alors les codes suivants :

L'interface a également été modifiée afin d'avoir une taille variable selon celle de l'écran. Celle-ci vérifie d'abord la taille actuelle de l'écran. Si cette dernière est inférieure à 600~px, l'interface bascule alors vers un affichage plus compact. De plus, si l'écran s'avère réellement trop petit, le principe d'un retour à la ligne flexible (\textit{flex-wrap}) est employé. Celui-ci vient simplement réaliser un retour à la ligne des colonnes, les superposant ainsi. Cela est réalisé comme suit :

\begin{minted}{html}
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ...
  /* Responsive (Téléphone) */
  @media (max-width: 600px) {
    .inducteurs-colonnes { gap: 15px; }
    .entete { font-size: 14px; }
    .valeur { font-size: 14px; width: 50px; padding: 4px; }
    .button { font-size: 24px; padding: 10px 20px; }
  }
\end{minted}

\subsection{Filtrage des données}
Les données affichées changeant très rapidement et régulièrement, des valeurs filtrées ont dès lors été envoyées. Ceci a été réalisé au moyen d'un filtre du premier ordre. Cela se fait très simplement au niveau du programme principal, comme suit :

\begin{minted}{c}
  Pos1_filt = (0.001 * Position1) + (0.999 * Pos1_filt);
  Pos2_filt = (0.001 * Position2) + (0.999 * Pos2_filt);
  Pos3_filt = (0.001 * Position3) + (0.999 * Pos3_filt);
  Pos4_filt = (0.001 * Position4) + (0.999 * Pos4_filt);

  Cur1_filt = (0.0001f * Current1) + (0.9999f * Cur1_filt);
  Cur2_filt = (0.0001f * Current2) + (0.9999f * Cur2_filt);
  Cur3_filt = (0.0001f * Current3) + (0.9999f * Cur3_filt);
  Cur4_filt = (0.0001f * Current4) + (0.9999f * Cur4_filt);
\end{minted}

Ceux-ci sont dès lors employés pour l'envoi des données :

\begin{minted}{c}
  UartCounter++;
  if (UartCounter >= 250)
  {
      UartCounter = 0;

      SendFloatAsText(Pos1_filt*1000, Pos2_filt*1000, Pos3_filt*1000, Pos4_filt*1000, Cur1_filt, Cur2_filt, Cur3_filt, Cur4_filt);
  }
\end{minted}
